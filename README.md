# Умный Закуп — автоматический расчёт заказов поставщикам

> Хакатон **HACKALEM AI** · кейс партнёра **ТОО «Электрокомплект» (ekt.kz)** · команда **Light**

Сервис для менеджера отдела закупа. Он заменяет ручной расчёт в Excel: за несколько секунд
формирует список рекомендованных заказов поставщикам. У каждой позиции есть понятное обоснование,
уровень срочности и выгрузка в Excel, совместимая с 1С.

---

## 1. Проблема

- Потребность в пополнении склада сейчас считается вручную в Excel, редко и не в реальном времени.
- Итог: **избыточные запасы** по одним позициям и **дефицит** по другим.
- Разовые крупные продажи (например, большой заказ одному клиенту) **искажают** расчёт регулярной потребности.
- Когда товара нет на складе, продажи равны нулю, и прогноз **занижается** (упущенный спрос не учитывается).

## 2. Решение

Менеджер выбирает поставщика (IEK / Systeme Electric), склад или категорию и нажимает «Рассчитать».
Затем он:

1. получает таблицу рекомендованных заказов, **сгруппированную по поставщикам**;
2. видит по каждой позиции **обоснование** («почему именно столько») и **срочность** (🔴 / 🟡 / 🟢);
3. при необходимости **корректирует** количество;
4. **утверждает** заказ и выгружает его в Excel.

> ⚠️ Сервис **никогда не отправляет заказ поставщику автоматически**. Решение всегда принимает ответственный сотрудник.

## 3. Входные данные

Данные партнёра лежат в папках `IEK/` и `Systeme electric/`:

| Файл | Содержимое | Для чего используется |
|---|---|---|
| `Динамика продаж_*.xlsx` | Строки расходных накладных: дата, номер документа, код 1С, товар, склад, количество | Поиск разовых крупных заказов, дневная история |
| `Ежемесячные продажи ...xlsx` | Продажи в штуках по месяцам, 2024–2026 | Базовый ряд спроса |
| `Ежемесячные остатки ...xlsx` | Остаток на начало каждого месяца | Поиск периодов stockout |
| `Товар в пути ...xlsx` / `Путь ИЭК ...xlsx` | Заказанный, но ещё не поступивший товар, с датами прихода | Вычитается из потребности |
| `Сезонность ...xlsx` | Продажи по месяцам в деньгах по годам | Сезонные коэффициенты |
| `MOQ ...xlsx` | Минимальная партия / кратность отгрузки | Округление заказа |
| Категория 2026 (в файле «Товар в пути» SE) | Категория товара (ABC) | Уровень страхового запаса |

Идентификатор товара во всех файлах — **код 1С** (`Номенклатура.Код`, например `200400085_`).
Данные о клиентах в расчёте **не используются**: заказ определяется только по номеру документа.

## 4. Методология расчёта

Расчёт выполняется для каждого артикула по шагам.

### Шаг 1. Очистка от разовых крупных заказов (выбросы)
Используем «Динамику продаж», где каждая строка — отгрузка по конкретному документу.

- Для каждого артикула считаем **медиану** размера отгрузки и **MAD** (медианное абсолютное отклонение).
  Эти оценки устойчивы к выбросам, в отличие от среднего.
- Отгрузка считается **разовым крупным заказом**, если выполняется одно из условий:
  - `количество > медиана + 5 × MAD` **и** больше 3 медиан;
  - одна накладная даёт **> 40 %** месячных продаж артикула.
- Такие отгрузки **исключаются** из регулярного спроса. Их можно посмотреть отдельно («Что исключено и почему»).
- Дополнительно месячный ряд обрезается по методу Хампеля: значения за пределами `медиана ± 3 × 1.4826 × MAD` сдвигаются к границе.

### Шаг 2. Восстановление упущенного спроса (stockout)
- Месяц помечается как **stockout**, если остаток на начало месяца ≈ 0 или меньше продаж этого месяца.
- Продажи в таком месяце не отражают реальный спрос. Мы заменяем их оценкой:
  `спрос = max(факт, средний спрос в месяцы с наличием × сезонный коэффициент месяца)`.
- В итоге потребность по таким артикулам **корректируется вверх** по сравнению с «сырыми» продажами.

### Шаг 3. Сезонность
- Сезонный индекс месяца `S[m]` = продажи месяца / среднемесячные продажи года, усреднённые по годам
  (из файла «Сезонность» — по поставщику; при достаточной истории — по категории или артикулу).
- Прогноз на следующие месяцы = базовый уровень × `S[m]`. Поэтому прогноз повторяет сезонный паттерн, а не просто среднее.

### Шаг 4. Тренд (устойчивый рост спроса)
- Сравниваем очищенный спрос за последние 6 месяцев с тем же периодом прошлого года (год к году).
- Рост ограничен диапазоном **−30 % … +50 %**, чтобы один скачок не раздувал заказ.
- Менеджер может задать ручной **прогноз прироста** (например, +10 % на рынок), и он учитывается в расчёте.

### Шаг 5. Потребность и заказ
```
Прогноз спроса на период покрытия  D = Σ (базовый уровень × S[m] × (1 + тренд) × (1 + прирост))
Страховой запас                    SS = z × σ(спроса) × √(срок поставки)   (z зависит от категории A/B/C)
Точка заказа                       ROP = спрос за срок поставки + SS
Потребность                        Need = D + SS − остаток − товар в пути
Рекомендуемый заказ                Q = округлить вверх Need до кратности MOQ (если Need > 0)
```
Каждый источник данных входит в формулу. Если изменить любой из них (например, товар в пути),
изменится и результат. Это требование п. 7.1 ТЗ.

### Шаг 6. Срочность
| Срочность | Условие |
|---|---|
| 🔴 Критично | Запаса (остаток + в пути) хватит меньше чем на срок поставки |
| 🟡 Скоро | Запаса хватит меньше чем на срок поставки + 1 месяц |
| 🟢 Планово | Остальные позиции с положительной потребностью |

### Шаг 7. Обоснование (объяснимость)
Для каждой строки формируется понятный текст, например:
> «Средний спрос 120 шт/мес (очищен от 1 разового заказа на 900 шт). Сентябрь — сезонный пик ×1.25.
> Рост год к году +12 %. В марте был дефицит — спрос восстановлен (+85 шт). Остаток 40, в пути 100.
> Нужно 330 → округлено до кратности 50 → **350 шт**.»

## 5. Выход

Таблица и дашборд с колонками:
`Поставщик · Код 1С · Артикул поставщика · Наименование · Категория · Остаток · В пути · Прогноз · Рекомендуемое кол-во · Срочность · Обоснование`

- Фильтры: поставщик, склад, категория, срочность.
- Ручная корректировка количества и кнопка «Утвердить».
- Экспорт в **Excel (.xlsx)** с кодами 1С для загрузки в учётную систему.
- Графики: тренды спроса по категориям и сезонный профиль.

## 6. Проверка требований ТЗ (Must have)

| № | Требование | Как проверяется в сервисе |
|---|---|---|
| 1 | Учтены все источники данных | Тест: меняем «товар в пути» → меняется рекомендация |
| 2 | Сезонность и рост | График прогноза для сезонного товара повторяет паттерн |
| 3 | Упущенный спрос | Для артикула со stockout: «до / после» восстановления |
| 4 | Разовые крупные заказы | Тест: добавляем искусственный заказ ×20 → рекомендация почти не меняется |
| 5 | Группировка по поставщикам + обоснование | Вкладки по поставщикам, у каждой строки есть текст обоснования |

## 7. Технологии

- **Python 3** + **pandas** — обработка данных и расчёт
- **Streamlit** — веб-интерфейс (дашборд, фильтры, редактирование, экспорт)
- **Plotly** — графики
- **openpyxl** — чтение и запись Excel

## 10. Приватность и ограничения

- Персональные данные клиентов не используются. Разовые заказы определяются по номеру накладной.

- Алгоритм устойчив к аномалиям: используются медиана и MAD, фильтр Хампеля и ограничение тренда.
